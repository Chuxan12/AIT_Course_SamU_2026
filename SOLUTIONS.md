## Данные и методика

В задании ЛР 1 под подписью «MNIST» прямо приведён `sklearn.datasets.load_digits`. Использован именно этот набор: **1797 изображений 8×8**, десять классов. Это не полный MNIST из 70 000 изображений 28×28. Загрузка не требует сети. Набор последовательно используется во всех четырёх работах.

Общие индексы разбиения: **1077 train / 360 validation / 360 test**, стратификация по классу, `random_state=42`. Интенсивности делятся на известный максимум 16. Среднее изображение вычисляется только на train и вычитается из всех частей. Для kNN достаточно деления на 16: общий сдвиг не меняет евклидовы расстояния. SVM получает дополнительную единичную координату для смещения. FC использует 64 признака, NumPy CNN — NCHW `(N,1,8,8)`, TensorFlow CNN — NHWC `(N,8,8,1)`.

Для kNN используется пятифолдовая стратифицированная кросс-валидация внутри train. Для SVM и нейросетей — отложенная validation; test не используется для выбора конфигураций. Требуемые в ЛР 1 исходные тестовые оценки kNN приводятся отдельно от выбора k. В Solver сохраняются вместе лучшие веса и соответствующие скользящие статистики BN. В опытах на переобучение используются последние веса, чтобы измерять результат ровно после 20 эпох.

Различие в один объект test соответствует примерно 0,28 процентного пункта, поэтому небольшие разницы нельзя считать убедительным преимуществом без повторных разбиений.

## ЛР 1: результаты и объяснение

Реализованы три способа расчёта L2-расстояний и голосование с выбором меньшей метки при равенстве голосов. Расстояния реализаций совпадают. Для k=3 средняя точность CV составляет 0.98328, стандартное отклонение по фолдам — 0.01269; при k=20 средняя точность падает до 0.95544. Слишком большое окружение сглаживает локальные особенности цифр.

SVM минимизирует `mean(sum(max(0, s_j − s_y + 1))) + reg·sum(W²)` при `j≠y`. Градиент штрафа равен `2·reg·W`. Максимальная абсолютная ошибка численного градиента меньше 1e-9 с регуляризацией и без. Циклическая и векторная версии loss/градиента совпадают; времена измерены в ноутбуке. Из девяти сочетаний lr/reg выбрано `(0.1, 0.001)` по validation. На данном разбиении локальный kNN обобщает лучше линейного SVM. Раздел softmax в ЛР 1 относится к вариантам 3–4; его функции также реализованы и проверены, поскольку softmax нужна в следующих работах.

## ЛР 2: результаты и параметры обучения

Архитектура: affine→ReLU→affine; функция потерь — численно устойчивая softmax cross-entropy плюс L2 без множителя 1/2. Разница с эталонными scores — 3.68e-8, с эталонным loss — 1.79e-13, максимальные относительные ошибки градиентов — менее 4e-9. На модельных данных loss снижается до **0.000526**, что ниже требуемых 0.02.

Проведено 12 опытов: ширины 32/64/128 × шаги 0.05/0.15 × L2 0.0001/0.001. Каждый опыт — 2000 обновлений, batch_size=64, decay=0.995. При равных лучших validation accuracy выбрана первая конфигурация, поэтому увеличивать число нейронов до 128 не понадобилось.

Параметры `train`:

- `X, y`: признаки и метки для обновления весов.
- `X_val, y_val`: отложенная выборка для контроля точности.
- `learning_rate`: длина шага SGD.
- `learning_rate_decay`: множитель шага после каждой эпохи.
- `reg`: коэффициент штрафа за большие веса; смещения не штрафуются.
- `num_iters`: общее число обновлений весов.
- `batch_size`: число случайных объектов в одном обновлении; выбор с возвращением.
- `verbose`: вывод прогресса обучения.

Число эпох здесь примерно `num_iters / max(N_train // batch_size, 1)`. В отличие от ЛР 2, в модульных сетях ЛР 3 используется соглашение `0.5·reg·sum(W²)` и производная `reg·W`, как требуют их проверки.

## ЛР 3: результаты экспериментов

- **Переобучение 50 объектов:** сеть с двумя скрытыми слоями по 100 нейронов достигает 100% train за 20 эпох при scale=0.1, lr=0.3. С четырьмя скрытыми слоями та же настройка даёт 90%; scale=0.2, lr=0.5 даёт 100%. Validation при этом около 74–75%: запоминание малого train не означает хорошее обобщение.
- **Оптимизаторы, шесть слоёв:** при scale=0.1 и 20 эпохах SGD с lr=0.03 даёт 67,22% val, momentum при том же шаге — 98,33%; RMSProp с lr=0.001 — 98,61%, Adam с lr=0.001 — 98,06%. Momentum и адаптивные методы сходятся быстрее при исследованных настройках. Это не утверждение об их превосходстве при любом подборе шага.
- **Batch normalization, 1000 объектов:** при малом scale=0.02 шестислойная сеть без BN остаётся около случайного уровня (10,28% val), с BN получает 98,61% за 10 эпох. Малые веса в глубокой сети ослабляют сигнал; BN помогает сохранить масштаб активаций.
- **Размер батча:** BN даёт 97,50% / 98,61% / 98,89% val при batch=10/50/100; без BN соответствующие опыты остаются около 10%. Различается не только шум оценки BN, но и число обновлений на эпоху, поэтому сравнение не изолирует исключительно качество оценки дисперсии.
- **Dropout, 500 объектов:** отсев 25% задаётся как `p=0.75` (вероятность сохранения). Без dropout val=93,06%, с dropout — 92,78% при 25 эпохах; улучшения в этом опыте нет. В обоих случаях train=95,60%. При прогнозе dropout отключён.
- **CNN:** на 100 обучающих изображениях train=100%, val=84,17%. На полном train лучшая из двух конфигураций получает 98,33% val и 95,83% test. Фильтры первого слоя визуализированы. Быстрые слои сопоставлены с прямой реализацией и численными производными; предусмотрен NumPy fallback без компилятора.

Для тестов BN с мини-батчем из двух объектов отдельные относительные ошибки весов достигают 1.1e-4 из-за малого знаменателя и конечного шага. Дополнительные проверки используют одновременно абсолютный и относительный допуски; полные градиенты сетей проверены отдельно.

## ЛР 4: результаты экспериментов

Требуемая CNN Conv5×5→ReLU→Conv3×3→ReLU→Dense→Softmax реализована через наследование Model, Sequential и Functional API. В Sequential дополнительно выполнены оба способа обучения: собственный GradientTape-цикл и `compile/fit`. Использован SGD с `momentum=0.9, nesterov=True`, lr=0.05. Subclassing CNN достигает **94,72% val после первой эпохи** (>50%). Различия результатов `fit` и ручного цикла связаны, в том числе, с порядком мини-батчей.

Для заключительного опыта используется Conv3×3(16)→pool2×2→Conv3×3(32)→pool2×2→Dense(64)→Dense(10), с ReLU и выходной softmax. Каждый опыт длится ровно десять эпох:

| Конфигурация | Val после 1-й эпохи | Лучшая val | Val после 10-й эпохи |
|---|---:|---:|---:|
| Adam, lr=0.001 | 46,11% | 94,44% | 94,44% |
| Adam, lr=0.003 | 77,22% | 97,22% | 95,28% |
| Adam 0.003 + BN + dropout 25% + L2=0.0001 | 68,61% | 96,39% | 96,39% |

Все три опыта превысили 70% за десять эпох. Шаг 0.003 ускоряет обучение относительно 0.001. Совместное добавление регуляризации и BN не улучшило лучший результат. Оно меняет сразу несколько факторов, поэтому отдельно оценить вклад BN, L2 и dropout по этому сравнению нельзя. У выбранной модели восстанавливается лучшая по val эпоха; test=96,39%. В ноутбуке приведены confusion matrix и precision/recall/F1 для всех десяти классов.

## Повторный запуск

Проверено с Python 3.13.13 на CPU. Из каталога репозитория:

```bash
uv venv .venv --python 3.13
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python tools/check_implementations.py
.venv/bin/python tools/execute_notebooks.py
```

В уже подготовленной рабочей папке окружение расположено уровнем выше репозитория: вместо `.venv/bin/python` используйте `../.venv/bin/python`. В VS Code выберите этот интерпретатор для ядра ноутбуков. Скрипт исполнения сам задаёт рабочую директорию каждого ноутбука, ограничивает потоки CPU и запускает отдельное ядро для каждой работы. Можно передать пути отдельных ноутбуков аргументами.

Необязательное Cython-ускорение (нужен компилятор C):

```bash
cd lab_3/scripts
../../../.venv/bin/python setup.py build_ext --inplace
```

Последний путь рассчитан на уже подготовленное окружение выше репозитория. При создании `.venv` внутри репозитория используйте `../../.venv/bin/python`. При отсутствии расширения ноутбук выполняется через NumPy fallback. Установленный Cython-модуль также проверяется тестами на прямоугольных ядрах, stride=2 и padding=0.
